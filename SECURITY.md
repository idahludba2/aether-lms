# Reporting security issues

Please do not publish private academic data, session cookies, tokens, or exploit details in a public issue.

If this repository has GitHub private vulnerability reporting enabled, use its **Security → Report a vulnerability** control. Include the affected version, a concise explanation, and reproduction steps using fictional files or data.

If that control is unavailable, open a public issue asking the maintainer for a private reporting channel without including vulnerability details. Do not assume a private channel exists until the maintainer supplies one.

Fixes are developed against the latest source version. There is no guaranteed response time or separately maintained older release series.

The extension preserves Sakai permissions and requires explicit copyright acknowledgement. Problems in the university service itself should be reported through the university's own support or security channel.
