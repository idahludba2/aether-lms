# Aether LMS v1.3.0 — resource roles, copyright and Office previews

Continues the existing production extension on `feature/v1.3`. The original v0.8.1 baseline and releases through v1.2.1 remain preserved in tags and release archives. Copy every release file into the existing unpacked extension folder, choose Reload in chrome://extensions and refresh LMS tabs. No permission or settings migration is required.

## Resources across roles

The previous classifier rejected an entire resource table when an upload field existed anywhere in its surrounding form. It also assumed fixed record widths and rejected native pagination/context rows whose span differed from the column count. Management views could therefore retain the original table even though student lists became cards.

Resource browsing is now classified from its records and the role of each control. Native action menus/selectors, bulk checkboxes, metadata columns, context/pagination rows and nested pagination tables remain usable. Header IDs and each cell's native `headers` relationship identify title and metadata when column counts or visible labels differ. Empty icon/action columns no longer add empty sections. Static dropdowns get a fallback position below the toggle; existing Popper positioning is retained.

Original elements, URLs, form names, selected values, hidden/CSRF fields and handlers are preserved. No add/remove permission or control is invented for students. Real editing fields still keep native table layout; switching back to browsing restores cards. OFF restores original semantics and elements. Same-origin TA resource frames receive the same treatment.

## Copyright within the preview

A shared descriptor recognizes native copyright links whose URL is stored in `openCopyrightWindow(...)`, along with ordinary file and folder links. Redirects are not followed to arbitrary destinations. The documented Sakai require endpoint supplies the notice, which is extracted as inert text.

The panel shows the notice and **Yes, accept and preview** / **Cancel**. Hovering never acknowledges a notice. Clicking Yes invokes the validated native same-origin acceptance endpoint for that exact resource, then reads the file into the same preview. Notice HTML/scripts/handlers are not inserted into the page. Permission denial remains an error; acknowledgement does not grant access. Native Open original retains its original link behavior.

## Local file readers

| Type | Preview |
|---|---|
| PDF | Existing local PDF.js reader and page navigation, including after copyright acceptance |
| PPTX | Static slide text, shapes, embedded images, tables and supported charts; Previous/Next and arrow keys |
| DOCX | Scrollable document text, tables and supported layout |
| XLSX | Visible worksheet selector, read-only cell values and stored formula results; formulas are not executed |
| ZIP | Entry names and uncompressed sizes; no extraction or executable content |
| Audio/video | Native paused controls for browser-supported formats/codecs |
| Image/text/code/CSV | Existing inert content previews, with broader filename and MIME recognition |

The actual package can identify extensionless Office downloads. Readers load only when needed into an extension-owned frame with no network connections, forms, child frames or executable document content. External PPTX media is blocked, Word alternative HTML chunks are disabled and document links cannot navigate. No academic file is uploaded to an external viewer. Bundle versions, license texts and provenance are preserved locally.

Limits: 12 MB PDF/image, 32 MB Office/archive/media, 128 KB text, 1 MB folder; six memory-cache entries and 24 MB total cache. ZIP metadata rejects encryption, traversal, duplicate paths, unsupported sizes and excessive entries. Office data is additionally streamed through decompression checks before rendering: at most 4,000 entries, 32 MB per expanded entry and 128 MB total. Slides are limited to 600; worksheet previews show at most 500 rows and 50 columns, with a visible notice when limited.

Legacy binary/encrypted Office formats, unavailable codecs and unsupported advanced Office effects retain Open original. Browser fonts and Office-specific layout can differ. These are static previews, not an Office editor or a guarantee of pixel-identical rendering.

## Verification

The actual unpacked MV3 extension was tested in isolated Chromium 149.0.7827.55 on Windows using intercepted fictional Sakai responses. The PPTX fixture contains text, shapes, an image, a table, a chart, literal script text and an external reference; DOCX/XLSX/ZIP/audio fixtures also contain only fictional data. No university account, real academic record or production add/delete operation was accessed.

The 26 new browser checks cover management, legacy and student resource views; native controls/values; editing transitions; OFF; same-origin frames; local Office content/navigation; notices, acceptance and rejection; extensionless URLs; damaged/oversized inputs; and TA cards plus Office previews at 360, 390, 640, 775, 1024, 1280, 1440 and 1920 px. They also verify that no request reaches the external test host. Existing folder/PDF previews, immediate hover dismissal, assignment forms, Gradebook/Roster, ordering, origin isolation and graphics checks remain passing.

Startup remains progressive: stars and the first folded-field frame appeared at 288.3 ms in the delayed-parser fixture, before DOMContentLoaded at 3056.8 ms. These are fixture observations, not live-server guarantees. Raw measurements and screenshots are retained in the versioned reports.

The final package's archive and per-asset hashes are in `release-v1.3.0-sha256.json`; ZIP/unpacked/source comparison is recorded in `reports/package-integrity-v1.3.0.json`. Development dependencies, test files and reports are excluded from the installable package.

Authenticated live LUMS and course-specific customizations remain unverified: no accessible live browser tab was available. The fixtures follow upstream Sakai structures and exercise role differences, but cannot prove every university customization. Native hidden-tab behavior remains the previously documented automation-host limitation and is not counted as passing. The sole permission remains `storage` and the original LMS host restriction is retained.
